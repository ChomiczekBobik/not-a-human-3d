# НЕТ, Я НЕ ВЕЛИЧАНИН (3D) — пародия на «No, I'm not a Human»

Статическая браузерная игра без сборки и без npm: Three.js идёт по CDN, а сцены,
риги, текстуры, GLB-модели и локальные OGG-эффекты подключаются как обычные файлы.
Заливается на GitHub Pages как есть.

## Запуск локально

Двойной клик по `serve.bat` (нужен Python) → открой **http://localhost:8080**.

Или вручную:
```
cd not-a-human-3d
py -m http.server 8080
```

Открывать `index.html` через `file://` нельзя — ES-модули по CORS не загрузятся.

## Публикация на GitHub Pages

Ниже — инструкция для отдельной публикации. Текущая локальная работа над шахтой, полевым архивом, бесшовными дверями, UI, PBR и оптимизацией **не публикуется автоматически**. В `VERSION` остаётся опубликованная ранее линия `0.1.0-beta.2`; запускать скрипты из этого раздела для новой сборки нужно только по отдельной задаче.

### Через GitHub API (без git и CLI)

Скрипт использует только Python из установленной системы и REST API GitHub.
Для матрицы файлов подходит Contents API: тяжёлые dev-артефакты исключены через `.gitignore`
и один общий список исключений; фактический состав и размер зависят от текущей версии.

1. Создай **personal access token (classic)** на `github.com/settings/tokens` со scope `repo`.
2. Не вставляй токен в чат или файлы. Установи его только в текущий PowerShell:
   ```powershell
   cd C:\Users\user\not-a-human-3d
   $s = Read-Host -AsSecureString 'GitHub PAT'
   $env:GITHUB_TOKEN = [System.Net.NetworkCredential]::new('', $s).Password
   Remove-Variable s
   ```
   После публикации: `Remove-Item Env:GITHUB_TOKEN`.
3. Проверь состав, сборку и опубликуй:
   ```powershell
   python tools\github_publish.py --dry-run
   python tools\build_release_zip.py
   python tools\github_publish.py --owner <твой_ник> --repo not-a-human-3d --enable-pages --release --asset dist\not-a-human-3d-0.1.0-beta.2.zip
   ```
4. Открой `https://<твой_ник>.github.io/not-a-human-3d/`. Первая сборка Pages занимает 1–3 минуты.

Скрипт создаёт репозиторий, если его нет, загружает файлы через Contents API,
включает Pages с ветки по умолчанию и создаёт prerelease `v0.1.0-beta.2`.
Если репозиторий уже существует — запроси токен, в котором есть Contents/Pages permissions,
и скрипт обновит файлы по SHA и прикрепит asset к релизу.

### Через сайт GitHub

1. Создай репозиторий `not-a-human-3d` → **Add file → Upload files**, загрузи распакованный
   `dist\not-a-human-3d-0.1.0-beta.2.zip`.
2. **Settings → Pages → Deploy from a branch → Branch: main → /(root) → Save.**
3. Через 1–3 минуты игра будет на `https://<твой_ник>.github.io/not-a-human-3d/`.

## Управление

### Компьютер

| Действие | Клавиша |
|---|---|
| Ходить | W A S D (Shift — быстрее) |
| Присесть / встать | C. В приседе — ниже камера, медленнее шаг и тише шаги |
| Действие / взять товар | E. Когда предмет доступен, вокруг него появляется тёплый жёлтый контур |
| Инвентарь | I или кнопка рюкзака. I / Esc / крестик закрывают панель; предмет используется кликом по карточке |
| Вернуть товар на полку | Q у выбранного товара; вне полки возвращается последний взятый. Сумма корзины показана справа сверху |
| День, время, список дел и полевой архив | TAB или кнопка «дела» слева; длинный список прокручивается колесом мыши |
| Смотреть | мышь (указатель захватывается кликом) |
| Вопросы, осмотр, решения | кнопки мышью в диалоге |
| Закрыть диалог / выйти из захвата мыши | ESC (клик — вернуться). Esc не отменяет уже принятое решение и не запирает допрос |
| Чит: пропустить ночь | набрать `homka` (или `рщьлф` — раскладка любая). Ночью — мгновенный скип. Днём/на титуле — армирование: в TAB появится `zzz`, ночь пролетит сама, когда ляжешь спать **[E] у кровати в спальне** |

### Телефон и планшет

Сенсорный режим включается автоматически при `navigator.maxTouchPoints > 0` и основном
`(pointer: coarse)` или `(hover: none)`. Ширина окна в определении не участвует: узкое окно на ПК
сохраняет клавиатуру и мышь, а ноутбук с сенсорным экраном и обычным указателем не переводится
насильно на телефонный интерфейс.

- **Левый джойстик** — аналоговое движение; **свайп по свободной части 3D-экрана** — обзор.
  Оба жеста работают одновременно разными пальцами и проходят через обычные коллизии и порталы.
- **ДЕЙСТВИЕ** — осмотреть, взять или поговорить; **БЕГ** и **ПРИСЕСТЬ** — независимые
  переключатели, их не нужно удерживать. В магазине появляется **ВЕРНУТЬ** для возврата товара.
- **ДЕЛА** и **ИНВЕНТАРЬ** остаются наверху. День, часы и архив прокручиваются в TAB;
  карточки инвентаря используются касанием. В глазке есть отдельная кнопка выхода.
- Pointer lock на сенсорных устройствах не запрашивается. Поворот экрана перестраивает приборы,
  джойстик и кнопки; учитываются safe-area вставки. Диалоги и прокрутка журналов остаются нативными.

## Меню, бесшовные двери и интерфейс

- Главное меню содержит только логотип, название, **«Играть»** и **«Настройки»**. В настройках оставлены три реально действующих параметра: качество рендера (`Авто`, `0`, `2`, `4`, `5`), общая громкость **0–100%** (по умолчанию **60%**) и чувствительность обзора мыши/свайпа **35–200%** (по умолчанию **100%**). Значения сохраняются в `localStorage` под ключом `not-a-human.settings.v1`; URL `?q=` остаётся приоритетной ручкой для воспроизводимой проверки.
- Между **домом ↔ улицей**, **улицей ↔ «Бедронкой»** и **улицей ↔ лицеем** нет загрузочных экранов. Подойди к двери: открывается именно видимый дверной pivot, а пересечение проёма клавишами WASD сразу переносит камеру в уже построенную сцену. Состояние адаптера не является оторванной копией: углы и `openAmount` читаются из живой двери. Работают движение вперёд, назад и по диагонали; **[E]** у двери остаётся альтернативным способом.
- Повторное срабатывание блокируется на **0,65 с**, но движение и рендер не останавливаются. Сюжетные ограничения и расход времени сохранены: дом → улица **20 мин**, улица → дом **20 мин**, улица → магазин **15 мин**, магазин → улица **15 мин**, улица → лицей **20 мин**, лицей → улица **15 мин**. Во второй день сначала нужно посетить лицей.
- Переходы в подвал, шахту и автоматическое наступление ночи намеренно сохраняют короткое затемнение: это смена вертикального уровня и игровой фазы, а не обычная дверь.
- HUD оформлен как полевой дневник и шахтёрский прибор: в основном экране остаётся только название локации; день/ночь и часы показываются в TAB и не дублируются в инвентаре. Инвентарь показывает карточки и описание выбранного предмета, а воздух и тепло имеют отдельные шкалы.
- **TAB и инвентарь** используют нативную прокрутку колесом, клавишами со стрелками, Space, PageUp/PageDown, Home/End и сенсорным свайпом. При открытии pointer lock снимается, фокус переходит панели без скачка страницы, при закрытии захват мыши восстанавливается там, где можно идти. Неизменённые списки не перестраиваются раз в секунду; необходимая перерисовка сохраняет `scrollTop`, узлы DOM и положение после закрытия/открытия.

## «Бедронка»: бесплатная выдача 1–3 предметов

- Денег в игре больше нет: они убраны из состояния, HUD, инвентаря, подарков, товаров, реплик Людмилы и ценников. «Бедронка» работает как **бесплатная ежедневная выдача**: за день нужно оформить у Людмилы **от 1 до 3 предметов**.
- Дневной лимит считается как `storePurchased.size + cart.length`, поэтому он общий на оформленное и на текущую корзину. Четвёртый предмет не берётся: подсказка меняется на «Дневной лимит: 3 предмета». Возврат **[Q]** освобождает слот, но не даёт обойти лимит.
- **[E]** берёт предмет с полки/витрины, **[Q]** или сенсорная кнопка **«ВЕРНУТЬ»** кладут его обратно. В магазине HUD показывает `0/3–3/3` и статус **«МИНИМУМ: 1 ПРЕДМЕТ»**, **«К ОФОРМЛЕНИЮ: N»** или **«ОФОРМЛЕНО»**.
- Касса и кнопка **«РАССЧИТАТЬСЯ · БЕСПЛАТНО»** сохранены как формальный ритуал. `checkout()` требует непустую корзину, начисляет ресурсы, добавляет предметы в журнал выдачи, очищает корзину и ставит `storeTripDone`. Пустая корзина не оформляется, поэтому минимум один предмет гарантирован.
- Пока выдача не оформлена, домой нельзя: это проверяют `canUseSurfaceDoor('street-home')`, `goHome()`, дверь **[E]** и физический бесшовный портал. Кровать вызывает `requestSleep()` и тоже отказывает. С неоформленной корзиной закрыт и выход из магазина — сначала расчёт или возврат.
- Автоматические 22:00 не телепортируют домой в обход магазина: при невыполненной выдаче время откатывается на **21:59**, один раз за день показывается предупреждение, а игрок остаётся там, где может завершить покупку. После оформления ночь наступает как раньше.
- Таблички на полках и витринах заменены на генерируемые **«ВЫДАЧА»**; стенды «ЖЁЛТЫЕ / полки на всё / ПО ВЫДАЧЕ», «МАСЛО / норма на день», «ХЛЕБ / свежий, почти» и «СДАВАЙТЕ / металлолом / ДОРОГО» остаются частью обжитого мира. Ценники `tag_*.png` больше не используются.

## Полевой архив и дополнительные детали мира

- В девяти сценах спрятаны **10 необязательных историй**: часы в квартире, лента и объявление на улице, служебная фотография в магазине, снимок 2-Б в лицее, зарубки в подвале и четыре находки на горизонтах шахты.
- Это настоящие объекты с геометрической подсветкой, а не невидимые зоны. **[E]** открывает полную историю; повторное действие позволяет перечитать запись. Найденный объект отмечается латунной печатью.
- Вкладка **TAB → ПОЛЕВОЙ АРХИВ** показывает счётчик **0/10–10/10**. До находки доступна только подсказка, после — название и отметка «ЗАПИСАНО». Основной список заданий остаётся над архивом.
- Находки не выдают деньги, сердца, фильтры и не заменяют основные концовки. За сбор всех десяти меняется свечение шва нулевой двери и появляется завершающий абзац архива.
- Дополнительная среда: сугробы и следы, провода и птицы, служебная дверь и зеркало магазина, бумажные журавлики, паутина и морозные узоры, пласты породы, крепёж и анимированные детали секретов.
- Контент находится в `src/expansion.js`, русские истории — в `src/secrets_story.js`. Декорации не добавляют коллайдеры и не меняют старые товары, точки появления, сюжетные цели и порталы.

## Текстуры и материалы

- Локальные PBR-карты **ambientCG**: `Wood051`, `Concrete034`, `Metal032`; используются Color, NormalGL, Roughness и для металла Metalness. Файлы лежат в `assets/tex/pbr/`, поэтому во время игры внешние серверы текстур не нужны.
- Источник: [ambientCG](https://ambientcg.com/), лицензия [Creative Commons CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/). Загрузчик с точными именами карт — `tools/fetch_pbr.py`.
- Плесень, царапины, потёки ржавчины, промокшая бумага и органическая грязь генерируются локально: `python -B tools\make_creepy_textures.py --size 1024`. Готовые файлы уже находятся в `assets/tex/generated/`; Pillow нужен только для повторной генерации, не для запуска игры.
- Расширение добавляет **15 локальных изображений**: цвет и нормали обоев, эмали, керамики и пластов породы; паутину, морозное кружево, следы и меловые зарубки; классную и служебную фотографии и детский рисунок. Повторная детерминированная генерация: `python -B tools\make_expansion_textures.py --size 1024`. Готовый набор лежит в `assets/tex/expansion/`; Pillow для игры не нужен.
- Декали прозрачные, не пишут глубину и смещены от опорной поверхности на **0,012–0,025 м**, поэтому не образуют coplanar z-fighting. Анимированные двери и декали на них исключены из статического батчинга; непересекающиеся следы с общим материалом объединяются отдельно.

## День, ночь и шахта «Величка-6»

- День начинается в **09:00**. Освещение квартиры, улицы, магазина и лицея постепенно снижается после **17:00**; в **22:00** Хомка автоматически возвращается домой, ночная смена начинается в **23:00** — но только если дневная выдача в «Бедронке» уже оформлена. Иначе часы останавливаются на **21:59**, и игра ждёт покупки, а не прощает её.
- На **третью ночь** в подвале открывается стальной люк. Спуститься через него можно только ночью; ночные стуки и рассвет ждут возвращения Хомки домой, пока он исследует шахту.
- Шахта состоит из четырёх отдельных сцен с разной геометрией, светом, туманом и опасностью. Каждый горизонт вырос до **16 × 26 м**: второй ряд крепи, боковые ниши с настилом, провисшие кабели, бочки, обломки, кости и белая шерсть. Прогресс, документы, экипировка, питание и состояния головоломок сохраняются между вылазками.
- **У каждого горизонта своя головоломка.** Верхний — три газовые заслонки; Затопленный — порядок насосов; Чёрный — давление 5 атм и запорный рычаг; Нулевой — эхо из четырёх плит. Ошибка стоит воздуха, но не запирает прохождение.
- **На чёрном горизонте просыпается белый жирный хомяк.** После запора давления начинается погоня: он идёт по коридору, двери можно захлопывать, чтобы задержать его, а в трёх шкафах — прятаться. В шкафу движение блокируется, монстр теряет цель и обнюхивает последнее место. Захват стоит сердца и возвращает Хомку к лестнице; на последнем сердце наступает концовка «БЕЛЫЙ ГОЛОД». Погоня сопровождается низким рыком, сердцебиением и пульсирующей виньеткой, но не постоянным фоновым гулом.

| Горизонт | Глубина | Основной шаг | Расход воздуха |
|---|---:|---|---:|
| Верхний | −12 м | Лампа, ключ сменщика, Стефан; выставить заслонки **ВЕРХ · НИЗ · ВЕРХ** | 0.10 %/с |
| Затопленный | −38 м | Осушить воду насосами **1 → 3 → 2**, вставить предохранитель, включить щит | 0.20 %/с |
| Чёрный | −71 м | Выставить **5 атм** двумя вентилями и зажать запор; пережить погоню | 0.42 %/с |
| Нулевой | не измеряется | Повторить эхо четырьмя плитами, коснуться белого света и выбрать | 0.70 %/с |

- **Воздух** показан отдельным HUD только под землёй. Фильтр из инвентаря восстанавливает **55 процентных пунктов**, не больше **100%**, и доступен при запасе ниже **96%**. Два фильтра спрятаны на нижних горизонтах.
- При **0% воздуха** теряется **1 сердце**. Если сердца остаются, Хомка возвращается на верхний горизонт с **55% воздуха**; иначе наступает концовка «СМЕНА БЕЗ КОНЦА». Во время перехода между сценами воздух не расходуется.
- Еда, аптечка и чай восстанавливают **1 сердце** при неполном здоровье. Чай можно использовать **1 раз в день**.
- Лом не нужен для обычного спуска, но открывает альтернативу «закрыть нулевой ствол». Белый осколок и закрытый ствол ведут к двум разным шахтным концовкам после седьмого дня.
- В шахте есть **8 документов**, расширенные диалоги Стефана и нулевого горизонта, дополнительные реплики Людмилы и Зоси. Тексты связывают меловые кресты, списки жильцов, Марека и краковскую колонну.

Для осмотра без прохождения доступны `#scene-mine1`, `#scene-mine2`, `#scene-mine3` и `#scene-mine4`; обычная игра начинается по корневой ссылке без hash.

## Звуки

Эффекты лежат в `assets/sfx/` и грузятся локально: во время игры внешний хостинг
звука не используется. Источники, исходные имена файлов и лицензии собраны в
[`assets/sfx/SOURCES.md`](assets/sfx/SOURCES.md). Записи из CC0-наборов — CC0-1.0.

Ночной эмбиент — четыре бесшовные петли `night_1..4.ogg` (по 292 с, четвёртая 341.58 с)
из трека владельца проекта: ночь 1 — 0:00–5:00, ночь 2 — 5:00–10:00, ночь 3 — 10:00–15:00,
ночь 4 — 15:00–20:49, ночи 5–7 по кругу с первой части. Петля запечена кроссфейдом 8 с
(`tools/make_night_ambience.py`), поэтому стык не слышен.

Старый глобальный синтезированный гул `_drone` удалён: `Sfx.init()` больше не создаёт
бесконечных осцилляторов. Ночной эмбиент запускается только ночью, ветер — на улице,

## Как править сюжет и персонажей

Все ночи лежат в `src/game.js` в массиве `NIGHTS`. У каждой ночи:
- `visitor` — параметры модели (передаются в `createHumanoid`);
- `lines` — две реплики перед диалогом;
- `questions` — вопросы игрока и ответы;
- `look` — то, что видно при осмотре в глазок;
- `goodOpen / goodClose / badClose` — тексты последствий;
- `human: true/false` — определяет правильное решение (нелюдь + «открыть» = смерть).

Добавить персонажа = добавить объект в `NIGHTS`. Добавить новую позу = функция в `pose` (`src/anim.js`)
+ `case` в `Game.updateVisitor`.

## Собственные модели (GLB)

1. Кидай исходники в `assets/models/src/` (GLB, текстуры внутри, любой разрешение).
2. Оптимизируй (Pillow уже ставится):
   ```
   py tools/optimize_glb.py assets/models/src/gena.glb -o assets/models/gena.glb
   py tools/optimize_glb.py assets/models/src/hero.glb -o assets/models/hero.glb --size 2048
   ```
   Выход: все текстуры <= 1024 px (или 2048 для героя), baseColor без альфы -> JPEG q90,
   normal/roughness/occlusion -> PNG. Оригинал не меняется.
3. Веб-файлы в `assets/models/*.glb` попадут в игру загрузчиком `GLTFLoader`.

Рекомендуемые размеры: гости квартиры 1024 px, герой крупного плана 2048 px.
Оригиналы из `assets/models/src/` на GitHub Pages не нужны — достаточно оптимизированных.

## Технически

- Three.js **0.169.0** по CDN (`unpkg`, `three/addons/` для PointerLockControls/OrbitControls).
- Риг не скиннинговый: сегменты-меши на суставах, ноль ассетов и нулевая загрузка.
- Требуется WebGL2 и свежий Chrome/Edge/Firefox. На телефоне автоматически используются Pointer Events и сенсорный интерфейс; на ПК — PointerLockControls. Оба ввода вызывают одни и те же игровые действия.

## Производительность

Игра рассчитана на слабые ноутбуки; локальные замеры выполнены на Intel UHD Graphics 620.

- **Ограничение бэкбуфера**: на desktop рендер не превышает **1920×1080**, в сенсорном режиме — **1280×900**, независимо от высокого `devicePixelRatio`. Множитель пересчитывается на resize. Это ограничение внутреннего рендера, а не CSS-размера окна.
- **Адаптивное качество** — лестница **100 → 90 → 82 → 74 → 66 → 58%** от выбранного предела. Раз в **2 с** качество снижается ниже **42 FPS** и повышается выше **57 FPS** с cooldown. Bloom отключается на `q4`, тени — на `q5`; композер всегда получает новый pixel ratio.
- **Кадровый лимит**: по умолчанию **60 FPS** в игре и **30 FPS** в меню. `?fps=0` снимает лимит для замеров, `?fps=30` задаёт предел 30 FPS.
- **Объединённая постобработка**: `RenderPass → AtmosphericBloomPass → OutputGradePass`. Bloom делает extract и четыре blur-отрисовки в **1/4 разрешения** по каждой оси; HDR readBuffer не перезаписывается. Один финальный `OutputGradePass` на `RawShaderMaterial` добавляет bloom, хроматическую аберрацию, **ACES**, **sRGB**, цветокор, виньетку и зерно. Отдельные composite и `OutputPass` не нужны; полноэкранных проходов после сцены — **6**, включая extract/blur. Шейдеры полностью перезаписывают bloom-target, поэтому пять избыточных clear на кадр удалены.
- **Тени по движению**: кубическая карта домашнего point-света обновляется на **12 Гц** только во время движения двери/NPC. В покое частых обновлений нет; смена сцены и последний кадр движения принудительно обновляют карту. В остальных сценах интервал обновления — **1 с**.
- **Статик-батчинг без потери интерактивности**: инстансы по параметрам геометрии и материала, корзины **4 м** по XZ; оставшиеся разные геометрии с общим материалом объединяются через `mergeGeometries`. В шахте дополнительно объединено неподвижное содержимое ladder/lift внутри `targets.up/down`, но сами корни остаются живыми для действий и геометрической подсветки. В магазине шесть одинаковых потолочных панелей инстансируются после создания; общий материал сохраняет мерцание.
- **Меньше работы CPU и DOM**: корзина обновляется событиями, а не каждый кадр; неизменённые HUD/ARIA writes пропускаются; журнал и инвентарь ключируют содержимое; desktop не вызывает touch-only обновления; look-delta и состояние touch UI переиспользуются, а семь флагов сравниваются битовой маской.
- **Предпрогрев шейдеров**: все **9 сцен** последовательно проходят `compileAsync()` с кадровой паузой; без поддержки асинхронной компиляции используется `compile()`. Статус — `__perf().prewarm`.
- **Переиспользование ресурсов**: кэши PBR, обычных и текстурированных материалов, плоскостей и декалей. Анимации расширения обновляет только активная сцена; счётчики — `__perf().resources`.
- **Коридор за входной дверью гаснет**: группа видна только во время открытия двери или осмотра через глазок и скрывается в остальное время.
- **Плоские недосягаемые поверхности**: потолки, пол и стены подъезда, задние двери соседей — односторонние плоскости вместо боксов; у невидимых потолков сняты текстуры и bumpMap.
- **Снег на улице** анимируется в вершинном шейдере, без пересчёта **1200 частиц** на CPU. Пул из двух PointLight обслуживает три уличных фонаря; вывеска и дверь «Бедронки» делят один источник.

Ручные настройки через URL:

| Параметр | Действие |
|---|---|
| `?q=0` … `?q=5` | фиксировать качество (0 — 100%, 5 — 58% без блума и теней) |
| `?fps=30` | ограничить кадры (по умолчанию 60) |
| `?fps=0` | без ограничения кадров |
| `?bin=3` | размер корзины батчинга, м (по умолчанию 4) |

Быстрый запуск на слабом ноуте: `http://localhost:8080/?q=4`.

Проверка активного режима в консоли браузера: `__perf()`; принудительно переключить: `__setQuality(4)`.

### Сопоставимый замер до/после

Условия: реальный локальный Chrome, ANGLE **Intel UHD Graphics 620 Direct3D11**, окно **1418×802**, devicePixelRatio/pixelRatio **1**, `?q=0&fps=0`, адаптивное качество выключено, bloom и тени включены. Для каждой сцены — **1 с** прогрева позиции и **2,5 с** измерения.

«До» — сохранённая **одна серия** перед этой оптимизацией, а не усреднённый эталон. «После» — **три новые серии** на визуально исправленном конвейере; FPS указан как медиана и диапазон, draw calls — медиана. FPS считается по фактически завершённым `post.render()`, дополнительно проверяются `requestAnimationFrame`, активная сцена, отсутствие исключений и полный prewarm **9/9**. Серия с потерянными render frames или неполноценной сценой отбрасывается, а не усредняется.

| Сцена | FPS до → медиана после (диапазон) | Draw calls до → после | Снижение calls |
|---|---:|---:|---:|
| Квартира | 44.4 → **60.2** (60.0–60.2) | 69 → **67** | 2.9% |
| Улица | 55.9 → **60.1** (59.8–60.6) | 124 → **122** | 1.6% |
| Магазин | 50.4 → **60.0** (59.9–60.0) | 191 → **184** | 3.7% |
| Подвал | 58.5 → **60.1** (59.9–60.2) | 50 → **48** | 4.0% |
| Лицей | 59.5 → **60.0** (59.9–60.2) | 56 → **54** | 3.6% |
| Шахта, −12 м | 58.5 → **60.1** (60.0–60.2) | 64 → **47** | 26.6% |
| Шахта, −38 м | 58.2 → **60.0** (60.0–60.1) | 66 → **49** | 25.8% |
| Шахта, −71 м | 59.9 → **60.0** (59.9–60.2) | 73 → **56.7** | 22.3% |
| Нулевой горизонт | 53.1 → **60.0** (60.0–60.1) | 44 → **31** | 29.5% |

Большинство значений упирается в **60 Гц/vsync**, поэтому разница выше этого предела не измеряется, а малые приросты около 60 FPS нельзя трактовать как точный GPU-выигрыш. Встроенная графика зависит от фоновой нагрузки; таблица — локальный результат, не гарантия для другого устройства. Уменьшение draw calls измерено отдельно и не зависит от vsync.
